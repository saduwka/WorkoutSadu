ТЕХНИЧЕСКОЕ ЗАДАНИЕ
Функция записи тренировок в приложении Workout


1. Описание проекта

Workout - приложение для учёта тренировок и прогресса в фитнесе.
Функция записи тренировок позволяет пользователю фиксировать выполненные упражнения, подходы, веса и длительность, чтобы отслеживать нагрузку и динамику результатов.


2. Цель

Дать пользователю простой и быстрый способ вести журнал тренировок: какие упражнения выполнялись, с какими весами и сколько раз, а также видеть историю по дням и отдельным тренировочным сессиям. Это помогает планировать нагрузки, избегать перетренированности и отслеживать прогресс.


3. Целевая аудитория

- Люди, регулярно занимающиеся в зале или дома (новички и продвинутые).
- Пользователи, которые уже тренируются по программе и хотят фиксировать выполнение.
- Тренеры, которые могут использовать приложение для собственных тренировок или примеров планов.


4. Основной функционал (только запись тренировок)

4.1. Создание тренировки
- Создание новой тренировки на определённую дату и время.
- Выбор типа тренировки (например: «Силовая», «Кардио», «Смешанная») - опционально.
- Название и/или комментарий к тренировке (например: «Ноги», «Грудь + трицепс»).

4.2. Добавление упражнений в тренировку
- Выбор упражнения из справочника (база упражнений приложения).
- Добавление нового упражнения вручную (название; целевая группа мышц - опционально).
- Задание порядка упражнений внутри тренировки (см. раздел 5).

4.3. Запись подходов и параметров
- Силовые упражнения: число подходов; для каждого подхода - вес и число повторений (обязательность полей согласовать с типом упражнения; минимум - повторения или факт выполнения подхода).
- Кардио: длительность (минуты); дистанция (км/м) - опционально; средняя интенсивность (например RPE 1-10) - опционально.
- Пометка подхода как «разминка» / «основной» - опционально.

4.4. Редактирование и удаление
- Редактирование параметров тренировки (название, комментарий, дата/время, тип).
- Редактирование списка упражнений в тренировке (добавить / удалить / изменить порядок).
- Редактирование и удаление отдельных подходов.
- Удаление всей тренировки.

4.5. Просмотр истории
- Список тренировок по датам.
- Фильтр по типу тренировки - опционально.
- Переход к деталям выбранной тренировки.

4.6. Повтор тренировки
- Копирование структуры прошлой тренировки (упражнения и подходы) в черновик новой тренировки с возможностью правки перед сохранением.


5. Модель данных: сущности, связи, обязательные поля, порядок

5.1. Сущности и связи (логическая модель)

- Workout (тренировка): одна сессия в календаре. Связь 1 → N с WorkoutExercise.
- Exercise (упражнение в справочнике): что такое «подтягивания», имя и справочные атрибуты. Связь M ↔ N с тренировкой реализуется через WorkoutExercise.
- WorkoutExercise (упражнение в конкретной тренировке): факт «в этой тренировке выполнялось это упражнение», порядок в списке, опциональные заметки к блоку. Связи: N → 1 к Workout, N → 1 к Exercise, 1 → N к Set.
- Set (подход): измеримые параметры одного подхода (вес, повторы, длительность и т.д.). Связь N → 1 к WorkoutExercise.

Зачем WorkoutExercise отдельно от Exercise: одно и то же упражнение из справочника может входить в одну тренировку дважды с разными подходами; подход всегда привязан к конкретному вхождению упражнения в сессию, а не к абстрактному Exercise.

5.2. Обязательные поля (минимум для MVP)

Workout: идентификатор; дата/время начала (или дата сессии); createdAt. Название или тип - по продуктовым правилам (допускается пустое название при наличии даты и упражнений).

Exercise: идентификатор; name (название). Остальное (группа мышц, заметки) - опционально.

WorkoutExercise: идентификатор; ссылка на workout; ссылка на exercise; orderIndex (целое неотрицательное, порядок среди упражнений данной тренировки).

Set: идентификатор; ссылка на workoutExercise; setIndex (порядок подходов внутри этого вхождения упражнения). Набор числовых полей - по типу упражнения/подхода; в ТЗ зафиксировать правило валидации (например для силовых: обязателен reps или пара weight+reps по выбранной политике).

5.3. Хранение порядка упражнений и подходов

- Порядок упражнений в тренировке: поле orderIndex у WorkoutExercise. При добавлении в конец: max(orderIndex)+1 для данного workout. При изменении порядка (перетаскивание): перенумерация всех WorkoutExercise данной тренировки (простой и предсказуемый вариант для небольших списков) либо иной согласованный алгоритм без дыр в индексах.
- Порядок подходов: поле setIndex у Set в рамках одного WorkoutExercise; при удалении/вставке - аналогичная перенумерация в рамках этого блока.

5.4. Каскадное удаление (согласованность данных)

При удалении Workout удаляются все связанные WorkoutExercise и все их Set.
При удалении WorkoutExercise удаляются все его Set.
При удалении Exercise из справочника - отдельная политика продукта (запрет при наличии истории / мягкое скрытие / замена на «неизвестное»); в MVP рекомендуется не удалять Exercise, если на него ссылаются WorkoutExercise.


6. Разграничение ответственности

- Workout: когда была сессия; общее название/тип/комментарий ко всей тренировке; при необходимости - общая длительность сессии (если ведётся таймер тренировки). Не хранить здесь веса отдельных подходов.
- Exercise: справочные данные (имя, группа мышц и т.д.), переиспользование между тренировками. Не хранить факт «сегодня сделал 5×80».
- WorkoutExercise: присутствие упражнения в конкретной тренировке, orderIndex, локальный комментарий к блоку в этой сессии.
- Set: все измерения одного подхода; валидация заполненности на уровне подхода/типа.


7. Экраны приложения

7.1. Главный экран (список тренировок)
- Список тренировок по датам (например последние недели).
- Для строки: дата, название/тип, краткая сводка (число упражнений; длительность или объём - опционально).
- Кнопка «Новая тренировка». Тап по строке - экран деталей.

7.2. Экран создания / редактирования тренировки
- Поля: дата, время, название/тип, комментарий.
- Секция «Упражнения в тренировке»: список с краткой сводкой по подходам; кнопка «Добавить упражнение»; для выбранного упражнения - ввод/редактирование подходов (на том же экране или модально).
- Кнопка «Сохранить» (создать или обновить).

7.3. Экран деталей тренировки
- Общая информация и полный список упражнений с подходами.
- Кнопки: «Редактировать»; «Удалить» (с подтверждением); «Повторить тренировку» (создать черновик новой с такой же структурой).


8. Пользовательские сценарии

Сценарий 1 - новая тренировка: приложение → главный экран → «Новая тренировка» → дата/время (по умолчанию сегодня) и название → добавить упражнения из справочника → для каждого ввести подходы → «Сохранить» → в списке появляется новая тренировка.

Сценарий 2 - повтор прошлой: главный экран → выбрать прошлую тренировку → детали → «Повторить тренировку» → открывается черновик с той же структурой → правка весов/повторов → «Сохранить» → новая запись за текущую дату.

Сценарий 3 - редактирование: главный экран → вчерашняя тренировка → детали → «Редактировать» → правка подхода / удаление лишнего упражнения → «Сохранить» → детали показывают актуальные данные.


9. Логика работы и обновление интерфейса

9.1. Создание и сохранение
- По «Новая тренировка» создаётся черновик (необязательно писать в постоянное хранилище до «Сохранить»).
- Обязательные поля перед сохранением: дата (по умолчанию); хотя бы одно упражнение в тренировке (WorkoutExercise).
- По «Сохранить» создаются или обновляются сущности Workout, WorkoutExercise (с orderIndex), Set (с setIndex).

9.2. Обновление экранов после изменений
- После успешного сохранения или удаления тренировки список на главном экране и экран деталей отображают актуальное состояние без ручного обновления (подписка на хранилище / инвалидация запроса / callback при закрытии экрана редактирования - конкретная реализация на усмотрение разработки при сохранении единого источника правды).
- После сохранения редактирования пользователь возвращается к деталям с обновлёнными данными.

9.3. Пустой список
- Заглушка: «У вас ещё нет записанных тренировок» и кнопка «Записать первую тренировку» → экран создания.

9.4. Ошибка сохранения
- Пользователь остаётся на форме; показ сообщения (алерт/тост); введённые данные не сбрасываются.

9.5. Удаление тренировки
- Подтверждение: «Удалить эту тренировку? Действие нельзя отменить».
- После подтверждения - каскадное удаление связанных данных; переход на главный экран; если список пуст - заглушка из п. 9.3.


10. Дополнительно (опционально, будущие версии)

- Фильтры: по типу тренировки; по диапазону дат.
- Сортировка: по дате (по умолчанию от новых к старым); в перспективе по длительности или объёму.
- Аналитика: прогресс по упражнению (например максимальный вес за период); графики по ключевым движениям.
- Авторизация и синхронизация: не входят в минимальный объём фичи записи; при появлении общей учётной записи тренировки привязываются к пользователю.
